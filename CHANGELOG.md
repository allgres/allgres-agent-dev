# Changelog

All notable changes will be documented here.

## Unreleased

- Rules for decision points (docs/decision-rules.md). For approvals and proposals an administrator can write ordered rules, each a condition and an outcome (approve, reject, ask the model, send to a person), read before the decision model; what no rule matches goes on to the model, then a person. Conditions are data read by one fixed evaluator (all / any, is, is not, is one of, starts with, contains). A rule that approves must name who or what it is about, is saved only after a confirmation that shows how it would have done on past decisions, and never approves an unknown outcome of an outbound call; its decisions are kept as `decided_by='rule'` with no gold label. New tables `decision_rules` and `decision_rule_checks`; actions `delegation.rules`, `delegation.rule_save`, `delegation.rule_set_enabled`, `delegation.rule_delete`, `delegation.rule_move`, `delegation.rule_backtest`.
- Decision model: one switch and a named list of points (docs/delegation.md). **Turn the decision model off/on** replaces *Turn everything off*: off asks the model nothing and leaves every decision with a person, and each point keeps its setting for when it is turned on again; with no model connected there is nothing to switch. Decision points are grouped by source (Approvals, Rooms, Teams) with a name and what each decides; a point nobody described is listed under its source. New tables `decision_delegation_switch` and `decision_point_meta`; action `delegation.switch`; `delegation.overview` carries `enabled`, `has_model`, `active` and each point's `category`, `title`, `description`.
- Faster pages. The dashboard asked for each page's lists one after another, so a page with ten lists (Connections, Settings) waited ten round trips; they are now asked for together (MCP servers loads in about 0.4 s instead of 1.3 s here). The Language list starts with your current language so it can no longer jump back while the list of languages arrives.
- Interface settings are kept per user in the database (docs/user-prefs.md), no longer in the browser: language, theme, the last page and tab, and the Canvas's panel states follow the person to any browser. The sign-in screen is English. Old browser-stored values are ignored (this also clears a stale language left by an older version). New table `user_ui_prefs`; actions `me.prefs_get`, `me.prefs_set`.
- Inference settings (docs/model-registry.md). An agent's settings (Agents → Edit → Reasoning and sampling) and each model's **Settings** in Models & prices hold effort (low to max), thinking (adaptive, with a token budget, or off; shown summarized or omitted), temperature, top P, top K, max tokens and stop sequences. The agent's value wins over the model's default, which wins over the server's. **Blank is not sent**: the fixed temperature 0.2 and max tokens 1024 for OpenAI-compatible providers are gone (some servers' own defaults now apply), and Claude gets max tokens 4096 when blank. Claude providers receive max tokens, stop sequences, thinking and effort only (temperature, top P and top K are rejected by current Claude models); other providers receive temperature, top P, top K, max tokens, stop and effort as `reasoning_effort`. The form disables what the chosen provider does not use and says so. The Canvas inspector's temperature field is unchanged.
- Models an agent may use. In an agent's settings, tick the models it may use (from the list in Models & prices); tick none and any model that is on is allowed. The agent's own model, a person's choice in General and a model picked for one task must be among them; a function or procedure's own override and a model experiment are the administrator's choice and are not held to the list. A model switched off in Models & prices is refused for everyone. An agent whose model cannot be used (none chosen, provider or model off, or not among the ticked ones) shows the reason in the Agents list and in its settings, and its turns fail with that reason instead of calling the model. New table `agent_models`; action `agents.set_allowed_models`; `agents.list` carries `allowed_models` and `model_issue`.
- Model registry. Models & prices shows each provider as a fold-open list of its models: on or off, a note, the price in and out, and who uses it. Add a model by name or from what the provider lists (a model an agent already uses is listed by itself). A model's **Use on agents…** puts it on every agent, on chosen ones, and on functions and procedures, and can make it the default for new agents; this replaces the old "Use one model for many" form. A model switched off cannot be put on agents, and a model still in use cannot be removed. New table `llm_models`; actions `models.registry`, `models.registry_add`, `models.registry_set`, `models.registry_remove`.
- Provider tests tell the truth. A 2xx is no longer "connected" unless the body is a model list (a chat reply for the chat test): LM Studio answers an unknown path with HTTP 200 and `{"error":"Unexpected endpoint or method"}`, which used to pass the test and then showed up in General as the agent's answer. Such an answer is now an error for the agent turn too. The Add and Edit provider dialogs have **Test connection** that tests the form's own values before anything is saved (a typed key is kept encrypted only until the call completes), optionally with a real chat message for a model name you give, and say what to try (add `/v1`, use `host.docker.internal`, check the key or model). A new address or key forgets earlier results. General has **Test model** for the provider and model you chose. Drop-downs and other native pop-ups follow the page theme. New actions `providers.draft_probe_start`, `providers.test_model`, `providers.test_status`.
- Languages and translation packs (docs/i18n.md). English is the default; the language is chosen in Settings → Language (the top-bar 한/EN button is gone). Translations are JSON files in `web/i18n/` (English text as key, sections, English fallback), served at `/i18n/<code>.json`, shared by the dashboard and the Canvas; `scripts/i18n_check.py` reports coverage.
- Menu: **People** is now **Users**. Functions and procedures are made from one **+ Create** screen on Abilities (pick which, fill it in, land back on the list).
- One shell for Dashboard and Canvas. The Canvas now opens as the body under the dashboard's own top bar (an iframe on the same origin), so only the body changes; the top bar has a fixed height and its buttons never move. The dashboard has a 한/EN switch (English first, shared with the Canvas) and a theme button that also drive the Canvas, which now uses the dashboard's colors. Korean covers the menu, tab hints, forms, tables and empty states; long help paragraphs and server messages stay English. `/canvas` still works on its own. Pages may now be framed by the same origin (`frame-ancestors 'self'`).
- Menu (dashboard). The sidebar is now hubs with tabs: Chat (General, Rooms, Projects, Team messages, each with a one-line hint), Activity (+ Schedules), Abilities (+ Memories), Connections (Models, APIs, MCP, Decision, Inbound), Settings (Access, Audit log, SQL). Teams and Agents stay on their own. A Dashboard | Canvas switch is in both headers; the duplicate Sessions mode in Chat is gone (Activity shows it).
- Copy an agent (docs/agent-clone.md). `agents.clone` makes a new agent with the same prompt, model, limits, permissions, rules and teams; memories, tasks and schedules are not copied.
- Canvas (`/canvas`, admin menu → Canvas): a board for building the organization. Add agents and nested teams from one **+ Add** menu (or start from an example team), drop one agent's card onto another to put it under that agent (a delegation line, an `agent` grant), give abilities named in plain words under a delegation ceiling, chat with any agent or General, start tasks (optionally on a per-task model), save a group as a reusable configuration, and see who actually handed work to whom in the Flow view. English and Korean; system agents hidden until asked for. New tables `agent_groups`, `agent_group_members`, `canvas_positions`, and `canvas_templates`, columns `agents.allow_task_model` and `tasks.llm_override`, and 15 `canvas.*`/`agents.set_task_model` RPC actions (sql/canvas.sql). The React source lives in `web/canvas`; the built page is committed as `web/canvas.html`, so building the extension still needs no Node.js.

- Image tags (docs/deployment/docker.md). For now only `:main` is published, moving with every merge to `main`; a `v*` release tag will publish `:<version>`, `:v<version>` and `:latest` once releases begin. Images carry the extension version and the commit as labels. The CNPG extension image is tagged the same way.
- Decision model delegation (docs/delegation.md). Per decision point: off, watch (the model is asked after a person decides and only compared), or hand over (a sure answer decides a new approval or proposal; anything else stays with a person). Handing over needs 10 compared decisions at the agreement bar and a limited set of agents; the model may reject, but a tool run or a proposal is only ever approved by a person; its decisions are kept as `decided_by='laya'` with no gold label. Evaluation reports are recorded and a checkpoint switch needs one that meets the bar. One button turns everything off. Needs a real worker (`tests/delegation_e2e.sql`).
- Creator (docs/creator.md). The creator agent now reads a versioned guide (`creator_guide`) and chooses: reuse what exists, a PL/pgSQL function, a usage document, or a pointer to an MCP server. New proposal kind `create_procedure`; every function or document proposal carries a check (body rules, compiles without running, secret scan) shown beside the approve button; an approved result can be given to chosen agents (`proposals.grant`). The mock model can be scripted with `MOCK_ACTION:` for tests.
- Teams (docs/teams.md). An agent can join a second team (it keeps its first team's limits); a team can have a window for work handed to it by others, taken by one agent or by a person who picks who (kept as a gold decision, one question per team); the task's result is written back to the handoff, which shows sender, taker, state and result. Shared notes for a team or the organization, read by agents as data, with read and write grants. New actions `teams.*` and `memory_scopes.*`, the agent `remember` action takes `scope`, and a Teams page.
- Auto rooms (docs/rooms.md). A room can be switched to `auto`: the lead's `PROPOSE` starts the task by itself. Allowed only with a lead, a cost limit above zero, at most 50 turns and depth 6, and priced models for every agent; the same checks run at each start, and a blocked proposal stays pending with a notice. The start is kept as a `room_task_confirmation` decision with `decided_by='llm'` and no gold label. New action `rooms.cancel_task` and a Cancel button on automatically started tasks.
- Assisted rooms (docs/rooms.md). A room can be switched to `assisted`: after an agent answers, an `@mention` of another member asks that member for a turn, unless the caller may not hand work to it (same "agent" permission as delegation), the chain is too deep (new `max_depth`, default 4), the room is out of turns or budget, or two agents have been passing it back and forth for six turns; each refusal is a notice in the room. Only the lead can propose a task, with a `PROPOSE @agent: ...` line; at most three wait, and nothing starts until a person confirms. A confirm or decline is kept as the person's own decision (`room_task_confirmation`, gold label, without what people typed in the room). New `room_proposals`, `room_turns.depth` and `caller_agent_id`; action `rooms.proposal_decide`. The built-in mock model can now be scripted for tests with a `MOCK_SCRIPT:` line in an agent's prompt.
- Rooms (Work → Rooms, sql/rooms.sql, docs/rooms.md). People and agents in one place: an admin makes a room, adds people and agents, and gives each agent a role (a text that says what it is asked to do there; it grants no permission). A person's `@agent` message starts a task for that agent with the room's latest messages and its role in the goal, marked as data; the answer is posted back to the room, a failure as a notice. A person can make a task from any message. Each room has a turn limit and a cost limit, can have a lead who answers when nobody is called, and can be closed. The room is `manual` only: nothing calls an agent unless a person does. New tables `rooms`, `room_members`, `room_roles`, `room_messages`, `room_turns`; ten `rooms.*` actions. Team messages are unchanged.
- Inbound events and scheduled connection checks (sql/inbound_events.sql, docs/inbound-events.md). An outside system can POST a signed event to `/inbound/<name>` (HMAC-SHA256 over timestamp and body, five-minute window, optional event id so retries are harmless, per-source rate limit, 64 KB cap, and every refusal answers alike). A source either holds events for a person to start or starts a task itself; the event reaches the agent only as marked data inside the goal. Enabled MCP servers and decision models are now checked every 15 minutes (which also catches changed tools), and connections that are not healthy and events waiting for a person show under Needs attention on Home. Also fixes the sidebar: with the new menu items it was taller than a short screen and could not be scrolled. New tables `inbound_sources`, `inbound_events`; `hmac_sha256` is built on PostgreSQL's `sha256()`, so no extension is needed.
- Decision model connection (Connections → Decision model, docs/decision-models.md). Connect an official `laya-serve` by address and key; Allgres checks `GET /health` and shows the loaded checkpoints, their revisions and device, or says the key is needed (a server with a key set shows only its status to a caller without it) or that it cannot be reached. Connecting hands no decision to the model; delegation stays off for every decision point. A new connection kind `decision`, `api_connections.status_detail`, health-check probes, actions `decision_models.list` and `decision_models.connect`; the APIs page lists only plain HTTP connections. A mock `/mock/laya/health` backs the tests.
- Connection tests and model prices. Each plain API connection gets a Test button (one GET with its credential: reachable, key not accepted, or cannot be reached, with the reason). A provider's connection test now keeps the prices a provider itself reports in its model list (OpenRouter's `pricing`, a LiteLLM proxy's `*_cost_per_token`), and Models & prices shows every listed or in-use model that has no price, who uses it, and what the provider says it costs, with one button to accept the reported price or all of them. Nothing is priced without a person pressing the button. New `llm_providers.reported_prices`, `mcp_probes.purpose`; actions `connections.test`, `model_prices.unpriced`, `model_prices.apply_reported`. The built-in mock now reports a price for `allgres-mock`.
- Sign in to an MCP server with OAuth (sql/mcp_oauth.sql, docs/mcp-servers.md). Choose "Sign in with OAuth" and press Sign in: Allgres finds the server's authorization server, gets a client id (typed, a Client ID Metadata Document served at `/oauth/client.json` over https, or Dynamic Client Registration), sends the browser through authorization code with PKCE (S256) and the `resource` parameter, checks the returned `iss`, stores the token encrypted, and renews it before it runs out. A refused renewal shows the server as needing a login. New tables `mcp_oauth_config`, `mcp_oauth_flows`, `mcp_oauth_tokens`, `mcp_oauth_jobs`; `api_connections.auth_kind` accepts `oauth`; actions `mcp.oauth_start`, `mcp.oauth_forget`, `oauth.callback`; routes `/oauth/callback` and `/oauth/client.json`. A mock authorization server under `/mock/as/*` backs the tests.
- MCP servers (Connections → MCP servers, sql/mcp_connections.sql, docs/mcp-servers.md). Paste a server address, see its tools, choose how risky each one is, and register it as a function and procedure an agent can be given. A tool cannot be registered until a person has chosen its level; write and move-equipment tools always need a person's approval each time (new `functions.requires_approval`, checked in the execution gate). If a registered tool's description or inputs change, or the server stops listing it, its function is switched off until approved again. The worker accepts plain JSON and event-stream replies, tries the 2025 handshake first and falls back to the stateless form with `Mcp-Method` headers, and reports a 401 or 403 as needing a login. New tables `mcp_tools`, `mcp_probes`, `mcp_risk_rules`; new `api_connections` columns `kind` and `health`; six `mcp.*` actions. Built-in mock servers under `/mock/mcp*` back the new tests. The APIs page now lists only plain HTTP connections.
- Plainer wording and next steps on empty screens. Empty tables now say what to do next (for example, "No projects yet. A project is a shared place to work with one agent; create one above."). Models & prices, APIs, Functions & procedures, Schedules, and Access & appearance open with a one-line explanation, and a function is described as a tool an agent can call, a procedure as a how-to it follows. No data or behavior changes.
- Home is rebuilt around what needs you: three **Get started** steps (connect a model, build a team, give it a first job) until they are done, then what is waiting for your decision (with Approve and Reject right there), what is in progress, what needs attention (a provider whose last test failed, failed tasks), and the old counters and workers folded under System status. The overview status reply gains `team_agents` and `completed_tasks`, which the steps use.
- Dashboard menu regrouped by what you are doing: Home; Organization (Canvas, Agents, People); Work (General, Projects, Approvals, Activity, Schedules); Abilities (Functions & procedures, Memories, SQL); Connections (Models & prices, APIs); Settings (Access & appearance, Audit log). What was one Settings page is the same panels shown a few at a time; Sessions, Tasks, and Logs moved from Audit to Activity; Users moved to People. Page ids are unchanged, so a saved page still opens. See docs/architecture.md.
- Approvals page: a Mine / All I can see toggle on the Approvals and Proposals tabs; routed requests show their role and when they open to a second role, and hide the buttons a user may not use. Admins get a Decisions tab (what has been recorded, with download of the training and evaluation sets), and a People page (accounts, roles, units, who holds which role, rules, delegation).
- Decision records (sql/decision_records.sql, docs/decision-records.md). When a person approves or rejects an approval request or a change proposal, Allgres now keeps an append-only record of the situation, the question as asked, and the answer, with a gold label, in the shape Laya's trainer and evaluator read. New tables `decision_points`, `decision_records`, `decision_labels`, and `decision_exports`; `decisions.export` returns `laya-train` / `laya-evals` JSONL with a train/eval split that never shares a situation. Secrets never enter a record. Five new admin RPC actions (`decisions.*`). Nothing is decided by a model; this only keeps what people decided.
- People, roles, and approval routing (sql/org_routing.sql, docs/approvals-and-roles.md). New tables `org_units`, `org_roles`, `org_memberships`, `approval_rules`, and `approval_delegations`; routing and decider columns on `human_approvals` and `change_proposals`; a rule routes an approval or proposal to a role, with escalation to a second role and time-boxed delegation. `approvals.decide` and `proposals.decide` enforce it and record who decided. `approvals.list` and `proposals.list` take `mine`. Eleven new admin RPC actions (`org.*`, `approval_rules.*`, `approval_delegations.*`). With no rule, behavior is unchanged.
- Canvas safety fixes. Drawing a delegation line now obeys the delegation ceiling: it is refused, with the missing grants named, when an agent above the line lacks a view, function, procedure, or HTTP host that the receiving agent (or an agent below it) holds. A system agent can no longer be the receiver of a line. The permissions editor's function picker lists every active registered function, not only `http_get` and `http_request`. A fresh install shows the "Build your first team" guide again (the seeded agents no longer count as a team), now above the seeded cards.

## 0.1.0-alpha.3

- Built-in mock now answers `GET /mock/models` (and `/mock/v1/models`) so Settings → Test connection works against the same endpoint bootstrap uses for a first chat.
- Dashboard onboarding marks step 3 complete after General has finished a turn, not only after a model is saved.
- Provider probe errors prefer a JSON `error` field over the raw response body, so a 404 is `not_found` rather than `{"ok":false,"error":"not_found"}`.
- Creating a regular user assigns the seeded `general` agent so Chat works on first login without an extra Users-page click.
- Dashboard folds `health_monitor` with System agents so the main Agents list is conversation agents, not the seeded maintenance example.

## 0.1.0-alpha.2

- Onboarding checklist, Chat General as a 1:1 conversation, selftest isolation, and first-run draft/project guards.

- PostgreSQL 16, 17, and 18 support.
